# Evaluation fixtures

`runner.py` evaluates persisted jobs and does not rerun a brief.  It emits
only aggregate check metrics by default.

## Offline retrieval ablation

To add a real retrieval ablation, first freeze a small, reviewable corpus and
hand-label the evidence paragraph IDs for every query.  Record the semantic and
reranker scores generated by each controlled run, then execute:

```powershell
uv run python -m eval.runner --database-url $env:DATABASE_URL --retrieval-ablation path/to/frozen-retrieval.yaml
```

The version-1 YAML contract is:

```yaml
schema_version: 1
dataset:
  id: public-pilot-v1
  description: Frozen public opinions and hand-labelled evidence paragraphs.
top_k: 3
rerank_candidate_k: 9
corpus:
  - id: opinion-1-p-2
    text: The stored paragraph text.
queries:
  - id: q-1
    text: The proposition being checked.
    relevant_paragraph_ids: [opinion-1-p-2]
    semantic_scores:
      opinion-1-p-2: 0.91
    rerank_scores:
      opinion-1-p-2: 0.98
```

Every score mapping must name every corpus paragraph exactly once.  This makes
the experimental input explicit and reproducible.  The result adds a
`retrieval_ablation` map plus `retrieval_ablation_metadata` to `latest.json`.
It reports retrieval precision@k, recall@k, and MRR only.  It deliberately does
not call those values proposition-judge accuracy; that would require a
separate, same-prompt judge run for each mode and labelled proposition verdicts.

Do not put private brief text, raw job IDs, or credentials in a fixture that is
committed to the repository.
