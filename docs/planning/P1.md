# P1 implementation plan — MVP: existence + quote fidelity

## Purpose and implementation boundary

P1 delivers the smallest end-to-end PinCite experience that is still faithful to
the product thesis: a user uploads a federal brief, sees every extracted case
citation, and can inspect evidence for whether the cited authority exists and
whether an attached quotation matches the real opinion. It must be useful to a
self-represented litigant, evidence-first, neutral in language, and honest when
the system cannot verify something. It is **not** a legal-advice, intent, AI-use,
or "good law" product.

This plan is constrained to P1. It does not pull forward proposition judging,
opinion-part verdicts, Browserbase investigation, GPTZero signals, Elastic
indexing, exports, or other later-phase work. The one approved exception is
ADR-010: P1 uses an in-process fuzzy search of the already fetched opinion for
the FR-QTE-004 closest-passage fallback; Elastic replaces that implementation in
P2 without changing its caller-facing result.

## Inputs reviewed

- `docs/OVERVIEW.md`: audience, values, safety language, and P1's evidence-first
  product purpose.
- `docs/TRACKS.md`: CourtListener owns primary resolution; OpenAI is reserved for
  claim extraction / proposition judging, Browserbase is P3 fallback, Elastic is
  P2 retrieval, and Sentry remains cross-cutting.
- `docs/SPEC.md`: P1 phase gate; FR-ING-001..004, FR-EXT-001..004,
  FR-RES-001..005, FR-QTE-001..005, FR-UI-001..006; API, data, reliability,
  security, and test requirements.
- `docs/adr/ADR-001` through `ADR-010`: in particular Python + FastAPI/arq,
  deterministic quote checking before LLMs, CourtListener-first resolution, SSE,
  the P0 storage boundary, and the approved P1 local closest-passage fallback.
- Current P0 implementation: FastAPI, Postgres, Redis/arq, shared upload volume,
  job lifecycle/SSE, and the simple upload/status UI work; the pipeline and
  verdict packages are deliberately empty. There is one P0 end-to-end test,
  a migration for `jobs`, and no P1 data model, parsing, CourtListener client,
  quote checker, or review UI yet.

## Scope contract

| Area | P1 delivers | Deliberately deferred |
|---|---|---|
| Ingestion | PDF validation, page-aware text extraction, normalisation and original-offset mapping; clear no-text-layer failure | URL/docket ingestion (P5), OCR |
| Extraction | Case citations (including short form, *id.*, and *supra*), antecedent links, pinpoints, and attached/block quotations | LLM proposition extraction (P2) |
| Resolution | CourtListener batch lookup, status mapping/disambiguation, rate-limited caching, and opinion retrieval for quote claims | P2 retrieval for every resolved authority; Browserbase/official-site fallback and four-level final existence (P3) |
| Quote fidelity | Deterministic normalisation, ordered segment alignment, verdicts, word diff, and local closest passage | Elastic-backed lookup (P2) |
| UI | Mode-aware upload, streaming annotated brief, click-to-source, and quote diff | Proposition rationale, investigator/live-view, filters/exports/signals |

The P1 exit gate remains the definition of done:

1. A federal brief with at least 20 citations produces an existence finding for
   every citation.
2. P1 exposes `VERIFIED`, `NOT_IN_DATABASE`, and `AMBIGUOUS` existence results
   as provisional CourtListener outcomes, never as accusations.
3. Quote fixtures, including ellipses and bracket alterations, return the
   specified verdicts and diffs.
4. The review screen presents live highlights, source click-through, and a
   word-level quote diff.
5. Findings appear as each citation finishes, rather than only at job end.

## Ordered implementation checklist

### 1. Establish the P1 shared contract and schema

**Spec constraints:** `SPEC.md` §7, §8.1–8.3, FR-SYS-001..003,
FR-EXT-001..004, FR-RES-001..005, NFR-REL-002, NFR-PRIV-001, ADR-008 and
ADR-009.

- Add a P1 Alembic migration for the data P1 writes: citation records (raw and
  normalised text, kind, antecedent, original page/span/pinpoint and case hints),
  quote claims, resolved sources, source paragraphs, lookup cache, and findings.
  Keep the schema congruent with the `SPEC.md` §7 names so P2/P3 additions are
  additive rather than replacements.
- Move the duplicated API/worker database model definitions into a small shared
  internal models package or an explicitly shared module. This is a P1 necessity:
  both services must read/write citations, sources, and findings. Preserve arq's
  async task model and idempotent job/citation identifiers.
- Define typed API/SSE models before UI work: `citations.extracted` includes the
  citation IDs and original-page spans; `finding.created` includes citation ID,
  check, verdict, confidence, and enough revision/order information for an
  idempotent client update. Add `GET /api/jobs/{id}/citations` and
  `GET /api/sources/{id}` as specified.
- Keep uploaded PDF paths server-side, retain the existing 24-hour expiry field,
  and ensure no service credential crosses the browser boundary.

**Acceptance / verification:** migration upgrades a fresh Postgres database;
API and worker can create and read the same P1 records; replaying a citation task
does not duplicate findings; endpoint response/SSE schema tests pass.

### 2. Build page-aware ingestion and safe job failure handling

**Spec constraints:** FR-ING-001..004, NFR-SEC-002, NFR-REL-001,
NFR-PERF-001, `SPEC.md` §11 ingestion tests, `OVERVIEW.md` §5 and §8.

- In `packages/pipeline`, implement PDF text extraction one page at a time,
  retaining original character ranges for every extract. Construct a
  normalised-processing view (de-hyphenation across line breaks, quote/dash
  canonicalisation, whitespace treatment, and only defensible header/footer and
  line-number removal) plus a reversible normalised-to-original offset map.
- Enforce the existing 25-MB cap; obtain and persist page count in the worker.
  Sniff/parse PDFs in the worker, not the API, and reject a missing text layer as
  `NO_TEXT_LAYER` with an understandable OCR-is-out-of-scope message.
- Make malformed PDF, extraction, and per-citation failures update the job and
  emit a typed SSE failure without stopping unrelated work. Do not expose document
  content in errors or Sentry tags.

**Acceptance / verification:** unit tests cover page/span preservation and each
normalisation rule; property tests generate whitespace/hyphenation variations;
integration tests exercise valid, oversized, non-PDF, malformed, and no-text
uploads; a 150-page performance fixture is measured without breaking the worker.

### 3. Extract citations, resolve antecedents, and attach quotations

**Spec constraints:** FR-EXT-001..004, `SPEC.md` §2/§7.1/§11 extraction row,
ADR-001, and `OVERVIEW.md` §6.

- Add eyecite to the Python pipeline and record every case citation before any
  network call. Retain raw source text and original span/page, normalised citation,
  citation kind, case/court/year hints, and any pincite pages.
- Resolve full, short-form, *id.*, and *supra* references deterministically to a
  prior full-citation antecedent. Persist unresolved references with an explicit
  resolution state; never omit them simply because an antecedent could not be
  established.
- Attach a quote only when it is in the citation's sentence, immediately previous
  sentence, or a associated block quote. Store original and processing spans. Do
  not introduce an LLM for P1 extraction; that would violate the phase ordering
  and expands the OpenAI role ahead of P2.
- Fan out independently by citation after persisting extraction and emit one
  `citations.extracted` event before per-citation work begins.

**Acceptance / verification:** fixture tests cover full/short/*id.*/*supra*,
unresolved antecedents, pinpoints, inline quotes, preceding-sentence quotes and
block quotes; citation-string fuzz tests preserve source spans and never silently
drop a parsed citation.

### 4. Resolve citations through CourtListener, with cache and rate control

**Spec constraints:** FR-RES-001..005, NFR-PERF-002..003, NFR-REL-001..002,
ADR-003, `TRACKS.md` §0/§3, and `OVERVIEW.md` §4–5.

- Implement an async CourtListener client with a typed adapter, recorded-response
  tests, bounded retries/backoff for `429`, and a shared Redis token bucket capped
  at the specified 60 valid citations/minute. Batch requests at no more than 250
  citations and 64,000 characters.
- Cache lookup results and retrieved opinions by normalised citation. Map the
  CourtListener responses exactly as FR-RES-002 requires and use case name/year
  to reduce 300 responses; retain all plausible candidates when ambiguity remains.
- For P1 resolved citations with an attached quote claim, fetch and persist the
  opinion text and available opinion-part/page metadata. Split it into
  deterministic local paragraphs for quote matching and source display; this is
  not an Elastic index. P2 extends this retrieval to every resolved citation.
- Publish an existence finding immediately after this work. A CourtListener miss
  is visibly provisional (`NOT_IN_DATABASE`), not a claim that a case is fake;
  do not call Browserbase in P1.

**Acceptance / verification:** unit tests cover every status mapping, candidate
disambiguation and cache key; integration/contract tests use recorded CourtListener
responses plus one opt-in live smoke; a concurrent load test proves the token bucket
prevents 429 cascades; one failed upstream request yields a source-unavailable
finding while the rest of the job completes.

### 5. Implement the deterministic quote-fidelity engine

**Spec constraints:** FR-QTE-001..005, `SPEC.md` §6.2 and §11.2, ADR-002,
ADR-010, `config/thresholds.yaml`, and `OVERVIEW.md` §5.

- Build the normaliser and aligner as pure, tested functions in
  `packages/verdicts`: NFKC; typographic quote/apostrophe/dash unification;
  whitespace collapse; de-hyphenation; footnote-marker treatment; case-folded
  matching while retaining original text for display.
- Parse permitted legal quotation conventions: ellipses become ordered required
  segments; bracket alterations match a permitted token/prefix/suffix; editorial
  bracket notes such as `[emphasis added]` do not create a discrepancy. Use local
  token-level fuzzy alignment against the resolved source paragraphs.
- Return the exact §6.2 verdict, similarity/confidence, evidence paragraph/span,
  and word-level diff. When threshold alignment fails, return the best local
  fuzzy-match paragraph as "closest actual language" under ADR-010. Record a
  `PINPOINT_MISMATCH` note only when the needed source-page data exists.
- Load thresholds from the committed configuration, do not tune them ad hoc, and
  require an ADR for a threshold change as the SPEC's change-control rule says.

**Acceptance / verification:** the ten required §11.2 fixtures pass, including
out-of-order ellipses and a negation flip; property/fuzz tests generate allowed and
disallowed alterations; real-opinion integration tests retain evidence/diff spans;
long-opinion profiling is captured. The quote checker makes no OpenAI call.

### 6. Orchestrate independent P1 work and complete the SSE lifecycle

**Spec constraints:** FR-SYS-001..003, FR-UI-006, NFR-REL-001..002,
NFR-OBS-001, ADR-007 and ADR-008.

- Replace the P0 single `process_job` body with an idempotent orchestration task:
  ingest once, extract once, enqueue one independently retryable citation task per
  persisted citation, and calculate terminal job status only after all work has a
  terminal outcome.
- Persist task/event state sufficient for safe reconnects. The P0 comment that
  only current status is recoverable must not remain the P1 behavior because P1
  needs reliable live finding updates. Use SSE (not WebSockets) and retain event
  ordering/last-event handling compatible with ADR-007.
- Add Sentry transaction/spans and `job_id`/`citation_id` tags around ingestion,
  extraction, CourtListener resolution, and quote alignment, without recording
  brief text.

**Acceptance / verification:** an E2E run shows `citations.extracted`, multiple
independently arriving `finding.created` events, and `job.completed`; deliberately
fail one citation/upstream call and prove other citations complete; retry tests
prove no duplicate findings; the trace links API, worker, and citation work.

### 7. Replace the P0 log screen with the P1 review experience

**Spec constraints:** FR-UI-001..006, `SPEC.md` §6.4, §8, NFR-UX-001..002,
NFR-PRIV-002..003, CON-LANG-001, and `OVERVIEW.md` §3–6.

- Retain the explicit *Before you file* / *Answering a brief* selection. After
  upload, render a split pane: the left is the original brief with offset-mapped
  citation annotations, the right is source text/paragraph evidence returned by
  the source API.
- Apply the P1 highlight colour from the worst completed evidence verdict, and
  show a label/icon/tooltip as well as colour. Pending and unavailable states are
  grey; a database miss is not styled or worded as a final red accusation.
- Subscribe to `citations.extracted` and `finding.created` events and update only
  the affected citation as data arrives. Clicking a citation opens and scrolls
  the source pane to the evidence paragraph; quote findings expose a word-level,
  escaped diff and the local closest-passage fallback.
- Use plain-language, neutral explanatory copy and the exact standard disclaimer
  from `OVERVIEW.md` §6. Do not add P2/P3/P4 controls merely as inactive UI.
  Mask document content from Session Replay configuration before enabling replay.

**Acceptance / verification:** Playwright covers upload, streaming annotation,
click-to-source, diff rendering, unavailable-source state, keyboard navigation,
and XSS-safe rendering of source text; visual/manual review confirms a non-lawyer
can identify what was checked and open the supporting language.

### 8. Validate the phase gate, document operational evidence, and tag P1

**Spec constraints:** P1 exit gate, `SPEC.md` §11–13 and §15, `TRACKS.md` §1,
§3, §5, and `eval/demo_briefs.md`.

- Add the specified unit, integration, contract, property/fuzz, E2E, performance,
  and security test coverage where applicable. Keep CourtListener API fixtures
  recorded and redact any credentials. Preserve the existing P0 E2E smoke test.
- Run the full P1 gate against one public federal brief with 20+ citations. The
  documented Fivehouse and Cole candidate sources are suitable public inputs, but
  choose only a file whose availability has been rechecked before the run.
- Verify the concrete P1 demo sequence: upload → extraction update → an existence
  result → a quote result → click the highlight → inspect real source text and
  diff. Record Sentry trace links and timing, then fix material breakage before
  tagging `p1`.
- Use conventional commits scoped by requirement group and include requirement IDs
  in the commit subject/body as `SPEC.md` §15 requires.

**Acceptance / verification:** all P1 gate bullets pass; tests are green; review
copy contains no intent/AI-use accusations; no secrets appear in browser bundles;
the P1 tag marks a repeatably demoable system.

## Explicit decisions needed before implementation

The following are documentation conflicts or missing design choices. They are
not silently resolved by this plan; each needs your direction and, where it
changes a requirement/verdict/phase gate, an ADR plus a `SPEC.md` version bump.

1. **`UNRECOGNIZED` does not have a P1 existence verdict.** FR-RES-002 requires
   `400 → UNRECOGNIZED`, while the P1 exit gate permits only `VERIFIED`,
   `NOT_IN_DATABASE`, and `AMBIGUOUS`; §6.1 also has no `UNRECOGNIZED` row.
   The safest interim implementation is to retain `UNRECOGNIZED` as a resolution
   state and expose a neutral grey/source-unavailable finding, never red. This is
   an inferred policy, not currently specified; approve it or define its exact P1
   verdict, UI colour, and P3 investigator behavior.

2. **P1 quote paraphrase detection lacks an authorised semantic provider.**
   §6.2 and fixture 8 require `PARAPHRASE_IN_QUOTES` at semantic similarity
   ≥0.85, but P1 has no Elastic paragraph index (ADR-010 correctly defers it to
   P2) and the stack does not select an embedding service/model for P1. A local
   embedding model would add an unplanned dependency and an OpenAI embedding call
   would expand the stated OpenAI role. We need an explicit ADR choosing a P1
   provider (or formally moving that verdict/fixture to P2); otherwise P1 cannot
   claim the complete §11.2 quote suite.

3. **The P1 source endpoint promises provenance before P3 provenance scope.**
   `GET /api/sources/{id}` is marked P1 and says it returns provenance, while
   FR-PRV-001 first requires a complete provenance record in P3. The P1 source
   pane needs at least CourtListener URL and retrieval method to show evidence.
   Decide whether P1 should implement full CourtListener provenance early (a safe,
   additive P3 capability) or amend the P1 endpoint to return only P1 source
   metadata until P3. Returning an invented/empty provenance object would violate
   the evidence-first promise.

4. **The P1 phase scope says `FR-ING-*`, but FR-ING-005 is explicitly P5.**
   This plan follows the individual requirement's P5 priority and excludes URL
   ingestion. Please confirm that interpretation; otherwise P1 would be expanded
   beyond its stated phase and need Browserbase work that `TRACKS.md` assigns P3.

## Validated recommendations

- Keep all P1 pipeline logic Python and async/arq: it serves eyecite directly
  (ADR-001), preserves P0's working worker topology (ADR-008), and does not
  undermine any sponsor-tool responsibility.
- Keep CourtListener primary and use no web fallback in P1: this respects the
  primary-source and no-accusation aims in `OVERVIEW.md`, CourtListener's assigned
  role in `TRACKS.md`, and the staged safety gate in ADR-003/004.
- Keep quote comparison deterministic, local to the resolved opinion, and free
  of LLM judgement: it directly implements the central value of reproducibility,
  complies with ADR-002, and preserves OpenAI/Elastic work for their specified
  P2 roles. ADR-010 explicitly validates the local closest-passage implementation.
- Build the split-pane evidence review before later analytics, signals, and
  exports: this is the P1 exit gate and the product's core promise to a
  non-lawyer, while leaving the sponsor integrations in the phases assigned by
  `TRACKS.md`.
